# ビンカラビンの共通仕様対応（2026-10-31）

対象登録・現在のURL・Pages設定は [common-spec-migration.md](common-spec-migration.md)。実装の進め方は、既存パズル/記録契約の固定、表示の15言語化、任意名と結果単位の再送、独立したプレイ回数の維持、ブラウザ検証、PR更新。配信は引き続き `index.html` 一枚で、開発用カタログ/テストを公開しない。

## 維持した仕様・文言修正

20本（16色+空4本）、1本4層、既存の基礎配置を瓶単位でシャッフル。上の連続する同色層を、空または同色が上の瓶へ容量の範囲だけ移す。無効な移動の手数加算、戻す操作の保存上限200件・手数復元、完成判定は変更しない。説明の「同じ色だけ」は不十分だったため「空か同色4層でいっぱい」に修正し、実装済みの完成条件を正確に書いた。

計測は既存のカウントダウン完了時から。クリア時間の小さい方が良い、`game_slug=binkarabin`、scale=1000、3桁表示、送信値 `Math.round(elapsedMs)` を維持。リタイアとホーム中断では公開スコアを作らない。既存 `binkarabinName`、`binkarabin:sound` / `binkarabin:volume` を引き継ぎ、既存スコア/参加者/端末設定を削除しない。

## 15言語と画面

参照サイノメ main `79b1e5733e725cd1148b10fa5699ba846e2bf57d` の ja/en/es/pt-BR/zh-Hans/fr/de/ko/ru/it/zh-Hant/id/tr/vi/th。各77文字列を翻訳し、ホーム・ルール・移動可否・選択/戻す案内・確認ダイアログ・結果・ランキング・設定・通信状態・X共有/コピーを対応させる。日本語固有の問題がなく、色ID/記号/正解判定は表示言語に依存しない。

`locales/*.json` を編集して `python3 tools/build-locales.py` でHTMLへ埋め込む。全キー/置換パラメータの一致と、編集元が実配信内容と一致することをCIで確認。ネットワーク取得不要なので翻訳読込がゲーム開始を待たせない。

保存 `binkarabin:language` →対応するブラウザ言語→英語。地域を含むブラウザ言語は基準IDへ合わせる。言語変更はテキスト再描画だけで、配置・選択・開始時刻・戻す履歴・手数・送信IDを変えない。小数精度は従来の3桁を保つ。

名前欄をホームへ移し、任意/公開条件/10文字上限を明示。Unicodeの文字数で確認し、空欄と空白は公開参加なし。名前の変更・消去は保存し、次のプレイから適用する。IME確定中のEnterで開始しない。長い訳や名前を折り返し、結果の再挑戦/共有/ランキングボタンを順位表の前へ移す。ホームとルールの縦スクロールを許可し、ピンチ拡大を一律禁止していたviewport設定を外す。

## 公開スコアとプレイ回数は別処理

名前・UUID・クライアント版は開始時に固定。正常クリアの確定値を `binkarabin:score-pending:v1:<UUID>` に保存してから `submit_score_once_shared_v1` へ送る。複数の未送信プレイを別キーで保持する。再読込/オンライン復帰/送信再試行は同じID・名前・点数・版を使う。送信成功の名前/整数値/重複フラグを照合し、そのIDだけ消す。旧 `submit_score` へ切り替えたり、不明な応答後に新しいUUIDで送り直したりしない。従来の「旧RPCを無条件で2回試す」処理を置き換えた。

**事前依存:** [実験場PR43](https://github.com/chameleonjp-lab/chameleonjp_lab/pull/43) の `common-score-receipt-v1.sql` を同PRの手順で適用/読み戻しし、ラッパーRPCを先に利用可能にする。本番SQLは未適用。適用前に新ゲーム版を配信すると名前ありスコアが待機するため、ゲームのマージ前に行う。ラッパーは既存 `submit_score` 集計を同じトランザクション内で一度だけ実行し、過去の記録を移し替えない。

従来の `record_game_play` はクリア/リタイア/ホーム中断の**別の集計**として維持する。空名は既存サーバー契約で `名無し` の `game_play_events` となり、この処理から公開ランキングのスコアは作られない。公開スコアに転用しない。この旧集計RPCには送信IDがないため、結果ごとに一度だけ試み、応答不明時は「未確認」と表示して自動再送しない。再読込でも重ねて呼ばない。ゲーム終了や公開スコアの送信・ランキング表示を、その集計の完了待ちにしない。

`binkarabin:result:v1` は直近の結果表示用。再読込では時間/手数/終了状態を復元し、既に存在する待機レコードだけを再送する。開始/ホーム移動はこの表示用キーだけを空にし、過去の待機IDは残す。保存領域の拒否/容量不足では同じタブ内の保持のみとなり、再読込後の保持を保証できない。

サーバーの参加者キーは従来どおり名前依存。**同名別人の分離・改名時の本人継続は未解決**で、過去スコアの所有者を推定して変更しない。

## ランキング・共有

実験場と同じ `get_best_score_ranking` を `p_limit=30` で読む。参加者集計後の最大30件を表示し、同名行の削除をしない。同点は `rank_no` を使い、境界の並びは既存RPCに従う。圏外の本人順位/参加者数を上位30件から推定しない。人数/プレイ回数は従来の `get_game_play_stats` 応答だけを使う。

読込中・記録なし・失敗・再取得を分け、リクエスト世代とプレイIDで古い応答を無視する。送信成功後に読み直す。集計の確認/公開スコア送信/順位読込はそれぞれ状態を表示し、読込成功が送信失敗を隠さない。

ホーム/結果のX共有は現在の登録済みURL `https://chameleonjp.codeberg.page/binkarabin/`、紹介または今回の確定時間/手数を表示言語で渡す。名前や推測順位は含めない。黒白ボタンから投稿確認画面を開き、ポップアップ拒否ではコピー可能な本文を残す。

## 効果音

既存の生成音の雰囲気を維持。移し元選択/戻す、移し替え、無効操作、クリア、リタイアに対応し、詳細表は移行文書末尾。今回の追加は音設定の翻訳、同時音源上限8、interruptedを含む音声再開の試行。操作60ms抑制、終了音優先、終了時disconnect、非表示停止を維持する。

初回on/50%、保存off/0を尊重。最初がミュート操作ならAudioContextを作らない。音声再開の成否はゲーム開始条件にしない。再開完了後に過去の音をまとめて鳴らす予約を作らない。実際の聴取・長時間実機負荷は未確認。
